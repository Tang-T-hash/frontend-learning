# 第 1 章 核心结论与决策

## 1.1 技术路线（最终定稿）

| 项目 | 决策 |
|---|---|
| **主语言** | **Python** |
| **Web 框架** | **FastAPI** |
| **关系型数据库** | **PostgreSQL**（P0/P1 学 SQL 语法用 MySQL 亦可，**P2 起统一 Postgres**，因向量扩展 pgvector 在 Postgres 上，可省一整套组件） |
| **向量检索** | **Chroma**（跑通概念）→ **pgvector**（正式项目） |
| **缓存** | Redis |
| **AI 层** | 大模型 API → Embedding → 向量检索 → RAG → 工具调用 |
| **前端** | **只用 JavaScript，学到「能调接口 + 做简单页面」为止**（收尾时间盒：3 天） |
| **暂不学** | Java、Go、C++、React/Vue 深入、模型训练、微服务、Kubernetes |

### 为什么是 Python 而不是 TypeScript

目标里明确含「AI 应用开发」，这个权重压过「复用既有 JS 基础」：

1. **AI 应用生态是 Python 原生的**：大模型 SDK、LangChain、LlamaIndex、向量库客户端、评测工具，全是 Python 先有、最全、文档最好。走 TS 路线会在后续每一步撞上「这个库 TS 版没有 / 这个教程是 Python 的」。
2. **JS 不会浪费**：前端演示界面、调自己的 API 仍要用；且从 JS 切 Python 是「降难度」（无 `this`、原型链、事件循环的坑）。
3. **切换成本最低的窗口**：现在才 5 个月经验，再拖 3 个月成本就高了。

### 必须诚实认识的代价

国内**纯 Python 后端岗位显著少于 Java**，大厂后端主力仍是 Java/Go。这条路线成立的前提是——**必须把 AI 应用能力做出来**，靠「Python 后端 + AI 应用」的组合定位去打，而不是去和 Java 选手抢纯后端岗。

**投递关键词（不要海投泛「后端开发」）**：Python 后端、AI 应用开发、大模型应用、RAG、Agent 开发。

## 1.2 关于「民办二本」：改的不是路线，是打法

大厂校招简历初筛确实存在学校背景门槛，民办二本通过初筛的概率明显低于 985/211。**这是筛选机制的客观现实，不是努力不够。** 但它可以绕开，而且绕开方式与技术路线合拍：

| 大厂卡你的东西 | 你能用来替代的东西 |
|---|---|
| 学历背书 | **线上可访问、有真实数据、能讲 20 分钟的项目** |
| 四级成绩 | 中小公司 / AI 创业公司**通常不卡四级** |
| 名校实习经历 | **日常实习**（门槛远低于暑期实习，全年可投） |

**你能控的只有三样，且全部与学校无关**：
1. **能跑的项目**（不是 GitHub 空仓库，是别人能点开的东西）
2. **有数据的故事**（「命中率从 62% 提到 81%」远胜「熟悉 RAG」）
3. **持续的证据**（GitHub 一年不断的提交记录）

**心态校准**：2027 年 2 月那场春招定位为「练兵 + 捡漏」，**不是「必须成功」**。主战场是 2027 年秋招——到那时有整整一年的积累。一段中小公司的实习经历，在秋招时的价值远超「我一直在准备但没实习过」。

## 2.3 阶段 2：后端基础（P0）｜2026-12-01 → 2027-01-10（约 5.5 周）

**内容**：

1. **MySQL / SQL：【审查修正】从 1 天加到 5–7 天**
   - 内容：装库建表增删改查 + 索引原理 + 事务 + `EXPLAIN`
   - **为什么必须加天数**：只给 1 天就进 ORM，会跳过 SQL 思维（不会去想「这条查询走不走索引」）。而面试的数据库环节是纯 SQL 八股：慢查询排查、索引何时失效、`EXPLAIN` 怎么看、事务隔离级别、MVCC —— 这些 ORM 一个都不教，你会用 `session.query()` 却不知道它生成了什么 SQL

## 2.4 阶段 3：AI 应用核心（P1，**RAG 独占**）｜2026-12-16 → 2027-01-15（约 4 周）

> **审查修正**：本阶段从「LLM API + LangChain + RAG + LangGraph + MCP 五样并进」改为「**RAG 独占**」；LangGraph 与 MCP 整体移到阶段 4 之后（4 月）。
> 时间与阶段 2 尾部重叠，因 RAG 需在 1/15 前上线。

### 为什么砍 LangGraph / MCP

- LangGraph 和 MCP 在优先级里本来就是 **P2（加分项）**，而阶段 3 的时间只够一样东西做深
- 2026 年后端/AI 应用面试的分布是：**RAG 必考且必深挖**，LangGraph/MCP 是「知道就加分」
- 光「RAG 专项」做扎实就需要 3–4 周（切分、embedding、向量库、检索、重排、评估，每步都要动手踩坑）。把 5 样塞进 4 周，结果是每样都只到「知道有这么个东西」
- 判断标准用一句话：「这东西我的产物会不会用到？面试会不会问？」—— 两个都否 → 砍掉不心疼

### 学习顺序

1. 裸调 LLM API（拿 Key 跑通，**若阶段 2 已预热，此步可 1–2 天完成**）
2. LangChain（**只学它怎么帮你少写代码**：能读懂 `Retriever` / `Chain` 在干什么即可）
3. **RAG 全链路（本阶段重心）**
4. **评估子系统（本阶段必须交付）**

### RAG 学习顺序

Embedding 原理 → 向量库（**先用 Chroma 跑通概念，正式项目转 pgvector**）→ 文档切分 → 检索 → 重排 → 评估，**每一步都必须动手踩坑**。

### 明令禁止

用 LangChain 的 `RetrievalQA` 一行封装交付。可以借框架少写代码，但**必须能讲清每一步做了什么**，否则面试问细节必挂。

### 产出

- 一个最小 RAG demo（扔进几个 PDF，能提问并带来源回答）
- **`evaluation/` 目录（评测集 + 评测脚本 + 结果表）**

### 【审查修正】评估子系统必须做成交付物，不能只是「能说明」

原文只写了「能说明切分长度和召回数量对效果的影响」——方向完全正确（很多人想不到），但**「能说明」太软**。面试官会追问：

> 「你说调整切分长度提升了效果——提升多少？怎么测的？测了多少条？」

若答案是「感觉变好了」，前面所有技术叙述的可信度归零。所以必须落成文件：

```
evaluation/
├── testset.json     # 40–50 条：{question, expected_answer, source_doc}
├── run_eval.py      # 一键跑评测，输出指标（可复现）
└── RESULTS.md       # 对比表格（见下）
```

`RESULTS.md` 目标形态：

| 实验 | 配置 | 检索命中率 Recall@5 | 答案准确率 | 平均延迟 | 单次成本 |
|---|---|---|---|---|---|
| baseline | chunk=800，无 overlap，纯向量 | 62% | 55% | 2.1s | ¥0.008 |
| exp1 | chunk=400，overlap=100 | 71% | 63% | 2.3s | ¥0.011 |
| exp2 | exp1 + 混合检索（BM25） | 78% | 70% | 2.6s | ¥0.011 |
| exp3 | exp2 + rerank | **81%** | **74%** | 2.9s | ¥0.013 |

（表中数字为示例格式，填你自己的真实测量值。）

# 第 5 章 用 AI 提效（Prompt 库 + 红线）

> 这是最大的杠杆。用对了提速 3 倍，用错了会毁掉学习能力。

## 5.1 铁律

> **把 AI 当私教和陪练，不当代写。凡是简历上写的东西，必须是你自己能讲清楚的。**

让 AI 帮你写代码没问题。但**如果你不能解释每一行为什么这么写，这段代码在面试中就是负资产**——面试官追问两层就崩了。

| ✅ 提速 3 倍的用法 | ❌ 毁掉你的用法 |
|---|---|
| 让 AI 解释报错**根因** | 让 AI 写完整项目 |
| 让 AI 出题考你 | 让 AI 写作业交差 |
| 让 AI 扮演面试官压你 | 复制粘贴不懂的代码 |
| 让 AI review 你的代码、**反问你哪里没真懂** | 让 AI 决定架构（你讲不出来） |

## 5.2 六个场景的现成 Prompt

### ① 卡在报错时

```
我在学 Python，运行下面代码时报了这个错：

【代码】（粘贴）
【报错】（粘贴完整 traceback）
【我的理解】我认为问题可能出在 XXX，因为 XXX

请：
1. 指出我的理解哪里对、哪里错
2. 解释报错的根本原因（不要只给答案）
3. 给我一个提示，让我自己修（先别直接给完整代码）
4. 如果我自己修不出来，再告诉我答案
```

> 关键在第 3 条。让 AI 先给提示而不是答案，收获会大 10 倍。

### ② 学新概念时（费曼式）

```
我是编程初学者，正在学【FastAPI 的依赖注入 Depends】。

请：
1. 用一个生活中的类比解释它是什么
2. 给我一个最小可运行的代码示例（不超过 20 行）
3. 告诉我"如果没有这个机制，代码会变成什么样"（对比）
4. 出 3 道小题考我，先不要给答案
5. 最后告诉我初学者最容易误解这一点的地方是什么
```

> 关键在第 3 条（对比）和第 5 条（常见误解）。

### ③ 设计项目时（当陪练，不当设计师）

```
我要做一个【校园知识库 RAG 问答系统】，我的技术栈是 FastAPI + MySQL + 大模型 API。

我的想法是：（写下你自己的设计）

1. 指出我的设计里 3 个最可能出问题的地方
2. 追问：为什么这么设计？有没有别的方案？
3. 如果用户量涨 100 倍，我的设计哪里先崩？

请注意：不要直接给我一个"标准答案架构"。我要自己想明白。
```

### ④ 代码 Review（每周一次）

```
请 review 我这段代码（Python / FastAPI）：

（粘贴代码）

请从这几个角度评审：
1. 有没有明显的 bug 或边界情况没处理？
2. 命名和结构是否清晰？有没有更好的分层方式？
3. 有没有安全问题（SQL 注入、越权、敏感信息泄露）？
4. 哪些地方我可能"写出来了但没真正理解"？请针对这些地方反问我问题。

最后请给我一个"如果面试官看这段代码会问什么"的清单。
```

> 第 4 条最值钱——AI 能精准找出你「照抄但不懂」的地方。

### ⑤ 八股复习（交互式出题，远优于看整理好的八股文）


## 5.3 三个配套习惯

1. **让 AI 帮你建「概念地图」**：每学完一个阶段，让它梳理知识关联，标出「必须熟练」与「知道即可」，并指出盲区。
2. **让 AI 生成「能力检查清单」**：要求输出可验证的具体能力（如「能解释 Depends 解决什么问题」），而不是「掌握 FastAPI」这种模糊目标。
3. **用 AI 记录并复盘（每周）**：粘贴本周提交记录 / 踩坑本，让它判断产出是否达标、学习模式有什么问题、给下周 3 条建议。

## 5.4 三条红线

1. **不要让 AI 写完整个项目。** 可以让它写一个函数、解释概念、review 代码，但**架构设计和核心逻辑必须你自己想**。
2. **不要复制看不懂的代码。** 每段 AI 代码你都要能解释作用。看不懂就让它解释，解释完还不懂就别用。
3. **不要让 AI 替你思考「为什么」。** 它擅长「怎么写」，但「为什么这么设计」必须你自己形成判断——**这才是面试真正考的**。

## 7.1 向量数据库选型（2026 实测结论）

| 档位 | 选择 | 理由 |

| **入门首选** | **Chroma** | 零配置、进程内启动，10 万级向量以内几行代码跑通 RAG；缺点过滤能力弱、不适合大规模 |
